* Current Working Items
Live list of what's open right now — not the full historical plan index (see
[[file:README.org][README.org]] for that, ordered by dependency, everything
DONE included). Each entry is just a link to its real plan/section for detail;
check it off and remove it once the item ships or is shelved.

- [ ] [[file:wkt-identify.org::*OPEN QUESTIONS][wkt-identify.org — should =GCR1= carry a =deprecated= flag?]] —
  the highest-value follow-up from the identification work: 109 of 431
  geographic and 890 of 2,274 projected Esri =.prj= fixtures match *more than
  one* registry CRS equally well, almost always a deprecated ESRI code beside
  its live twin, and =identify_from_wkt= reports all of them rather than
  guessing. =proj.db= has the column; the blob does not. Adding it is a =GCR1=
  v3 format change plus a regeneration, and carries a policy question of its
  own (preferring live over deprecated is a judgment — it belongs in
  =identify.rs=, not =resolve=).
- [ ] [[file:public-api.org::*MILESTONES][public-api.org — R6e, the acceptance test]] —
  confirm a consumer with *no* =geosetta= dependency (=nazca=, or a throwaway
  smoke-test crate) can depend on =geoscribe= alone and resolve a real code.
  =nazca= already has the path-dep and the feature but calls nothing yet. The
  plan flags this as the actual point of R6, not an afterthought.
- [ ] *Publish =v0.4.0= under the =geoscribe= name* — =v0.2.0= shipped as
  =geosetta-crs-data=; the GitHub rename is done, crates.io is not. Once live,
  yank every =geosetta-crs-data= version to point dependents at the new name.
  =0.3.0= (R6's public API) and =0.4.0= (=identify_from_wkt=) are both tagged
  but unpublished, so =0.4.0= is the first crates.io release under this name.
  The =geosetta= version pin that [[file:public-api.org::*RISKS][public-api.org § RISKS]]
  flagged no longer exists — geosetta 0.24.0 dropped the dependency.
- [ ] [[file:envelope-computation.org][envelope-computation.org]] — dimension-aware
  bbox computation: a =Coord=/=Envelope= pair of this crate's own plus the
  =envelope()= entry point, so =geosetta= stops dropping a source GeoPackage's
  cached envelope. Scoping only.
- [ ] [[file:envelope-computation.org::*OPEN QUESTIONS][envelope-computation.org — how does a non-CRS capability gate in?]] —
  whether envelope computation shares =geosetta='s =crs-registry= feature, gets
  its own, or something else. Blocks the plan above and gets more pressing with
  every capability added. See also =../../architecture.org='s § OPEN QUESTIONS.
- [ ] [[file:envelope-computation.org::*OPEN QUESTIONS][envelope-computation.org — how far does the charter extend?]] —
  "own whatever geospatial metadata isn't a simple pass-through" is an easy bar
  to satisfy sloppily. The risk isn't this addition; it's that the *next* one
  gets less scrutiny than this one did.
- [ ] [[file:crs-registry.org::*RISKS / REMAINING OPEN QUESTIONS][crs-registry.org — table currency]] —
  the registry is only as current as the =proj.db= it was generated from; a
  newer EPSG release means regenerating the blob *and* re-checking attribution.
  No trigger for this exists today.
- [ ] [[file:crs-registry.org::*RISKS / REMAINING OPEN QUESTIONS][crs-registry.org — snapping tolerance]] —
  exact vs. epsilon on parameter values in name/param-match validation; err
  toward *not* snapping. Governs recovery paths 2/3 only (inline ids are
  trusted).
